FlightTrack

A real-time flight tracker built around a data source that updates far more slowly than the interface needs to. React 19, TypeScript, Vite and MapLibre GL JS over WebGL. The OpenSky API polls on a 60 second cycle, so aircraft sat frozen and then jumped; dead-reckoning interpolation now runs at 10fps between polls, and an early poll fires when a projected position drifts too far from the last known waypoint.

Defensive throughout, the way six years of embedded work taught me to be: geolocation degrades from GPS to IP to a default, rate limits back off behind a visible countdown, polling pauses on the Page Visibility API, and the map has a state for WebGL being unavailable. Vitest and React Testing Library for units, Playwright for the flows.

TabletHub

Kotlin and Swift are personal-project languages for me, not professional experience. What this was for was the debugging.

A native ambient display, built twice: an Android DreamService in Kotlin and Jetpack Compose, then a persistent iPadOS app in Swift and SwiftUI, same feature set on both. 3,250 lines across 26 files, four REST APIs, on-device ML for subject detection — MediaPipe on Android, Vision on iOS. 11,500 photos in live rotation on a physical tablet.

The iOS build deadlocked. Synchronous Vision work inside Swift task-group children was starving the cooperative thread pool, and it was invisible in the Simulator, where Vision throws immediately instead of doing the work. I found it by writing breadcrumbs to UserDefaults and pulling them off the device with devicectl. Moving the work to a dedicated queue behind a checked continuation cleared it: 10,822 photos scanned in about five minutes, no deadlocks.

Multi-agent development workflow

A daily-use setup where Google’s Antigravity IDE delegates discrete implementation tasks to Claude Code, across two vendor ecosystems. Every unit of output gets reviewed and corrected before it ships. The operating rule is the one I carried out of six years debugging embedded JavaScript in environments I did not control: never accept output I cannot explain.

career-ops is what came out of it — an agentic pipeline that scans, scores and tracks roles against a framework I defined: comp floor, stack fit, geography, interview-loop signal, narrative alignment. The scanner stage hits ATS REST APIs directly before any model call, so cost stays proportional to signal rather than to volume. 100+ roles evaluated, 126 structured reports generated.
